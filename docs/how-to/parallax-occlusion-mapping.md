# Use Parallax Occlusion Mapping in Unity URP

TextureWorks exports a height field and provides
[`unity/TextureWorksParallax.hlsl`](../../unity/TextureWorksParallax.hlsl) for a
Shader Graph Custom Function. The function traces the camera ray through the
height field and returns the UV used to sample the material. It works with
height maps generated by either the CuPy or PTX backend.
An optional `TextureWorksParallaxSurface` entry point also returns a normal
derived from that height field, using the same depth, filtering, and fades.
The [algorithm contract](../reference/parallax-algorithm.md) specifies the ray,
intersection search, and bypass behavior.

## Generate and import the maps

```powershell
.\.venv\Scripts\python.exe -m textureworks.pipeline textures/test_texture3.png --height-bits 16 --output output/
```

This produces the usual six files, with a 16-bit grayscale height PNG. To export
an existing float height array through Python, call `save_map(height, path, bits=16)`.
Height remains linear `[0, 1]`, black low and white high. The existing height
generator derives relief from luminance; inspect that relief before tuning the
shader. Lighting and painted markings in an albedo image can become false depth.

Copy the HLSL file into your Unity project's `Assets` directory. Import the height
PNG as **Single Channel**, selecting **Red**, with sRGB disabled, mipmaps enabled,
and bilinear/trilinear filtering. Select
an uncompressed R16 format through the platform override and verify the resulting
runtime format. Import settings can reduce the precision of a 16-bit source PNG.
Set the maximum texture size to retain the resolution you intend to use.

Choose Repeat for a repeating material and Clamp for a single texture region.
The function uses the height texture's sampler. A repeating sampler does not make
a texture seamless; all maps in the set must share suitable edges and alignment.

Import albedo as color, the normal map as a normal texture, and scalar roughness,
metallic, AO, and specular as linear data. All maps must describe the same UV region.

## Add the Custom Function

Create a URP Lit Shader Graph and a Custom Function node with **Type: File**,
**Source: TextureWorksParallax.hlsl**, **Name: TextureWorksParallax**, and
**Precision: Float**. Enter the name without `_float`. The node is for the fragment
stage. The wrapper uses Shader Graph's `UnityTexture2D` texture input.

Create these ports in order:

| Input | Shader Graph type | Suggested starting value or connection |
| --- | --- | --- |
| `HeightMap` | Texture 2D | Height texture property; red channel is sampled |
| `UV` | Vector 2 | UV0 after your shared Tiling And Offset node |
| `ViewDirectionTS` | Vector 3 | View Direction node, Tangent space |
| `HeightScale` | Vector 2 | `(0.03, 0.03)` for an initial visual check |
| `MinSteps` | Float | `16` |
| `MaxSteps` | Float | `64` |
| `RefinementSteps` | Float | `6` |
| `ViewDistance` | Float | Distance between Position (World) and Camera position |
| `FadeStart` | Float | `10` world units |
| `FadeEnd` | Float | `20` world units |

| Output | Shader Graph type | Meaning |
| --- | --- | --- |
| `ParallaxUV` | Vector 2 | Corrected coordinate for every material sample |
| `Depth` | Float | Intersection below the top of the slab, `[0, 1]` |
| `InBounds` | Float | `1` if the returned UV is inside `[0, 1]` on both axes |

### Match lighting to the height field

For a height-only material, set the Custom Function name to
**TextureWorksParallaxSurface**. Keep the same inputs and three outputs above,
then append **NormalTS**, a **Vector 3** output. Connect it directly to the URP
Lit graph's **Normal (Tangent Space)** input. This vector is already normalized;
do not pass it through a normal-map unpack node.

This variant computes four neighboring height samples at `ParallaxUV`, uses the
same UV gradients as the trace, and scales the slope by the effective
`HeightScale`. Its lighting flattens with the same distance and angular fades.
It is useful for checking whether the visible surface agrees with its relief.

TextureWorks' existing normal generator operates on albedo gradients. Its
strength, smoothing, and contrast do not automatically match a separately
generated height map's physical depth. Use `TextureWorksParallaxSurface` for
coherent height-derived lighting, or the original `TextureWorksParallax` with an
authored normal map that matches the height. Detail normal blending is a separate
material choice. A coherent normal cannot fix an incorrectly inferred height.

The view vector points **from the surface toward the camera** in the mesh tangent
frame. Supply valid tangents; a zero vector, back face, or almost grazing view
bypasses the trace. Mesh UVs, normals, tangents, and normal-map orientation must
agree. The height texture property's own tiling/offset is not applied internally.

`HeightScale` is depth expressed in the **final sampled UV coordinate units**,
independently for U and V. It is not a value in meters or centimeters. For a flat
patch spanning `Lu` and `Lv` world units per original UV square, desired depth `d`,
and positive tiling `(tu, tv)`, use `(d * tu / Lu, d * tv / Lv)`. This relationship
assumes an orthonormal tangent frame and uniform UV density on that patch. Mirrored
or nonuniformly scaled mappings need a corresponding tangent/UV transform.

## Sample the material at the corrected UV

Connect `ParallaxUV` to the UV input of every Sample Texture 2D node: albedo,
normal, AO, roughness, metallic, and specular when used. Apply shared tiling and
offset before the Custom Function, once. Mixing original and corrected UVs makes
the material layers slide apart.

In a metallic URP Lit graph, connect albedo to Base Color, normal to Normal
(Tangent Space), AO to Occlusion, metallic to Metallic, and `1 - roughness` to
Smoothness. A specular workflow can instead use the specular map according to the
graph's chosen material contract. Height drives the trace rather than a lighting
input. The generated scalar specular map is a heuristic, not measured F0.

For a repeating material, leave `InBounds` unused: valid tiled coordinates routinely
exceed `[0, 1]`. For a single UV square, it can drive Alpha with Alpha Clipping
enabled and a threshold of `0.5`. This only clips the square's edge. It does not
handle atlas islands or produce displaced geometry; verify every generated pass
before using this clipping in a production material.

`Depth` describes the intersection in the virtual slab. It is **not** a device
depth value and must not be wired directly to a depth output. The supplied include
adjusts texture sampling. It does not move vertices, write camera depth, or trace
light rays for self-shadowing. Cast shadows and silhouettes therefore retain the
mesh geometry. These limits also affect depth-based screen effects.

## Tune quality and cost

Sample count increases toward grazing views between `MinSteps` and `MaxSteps`.
The function rounds and clamps these to `[1, 128]`, with the minimum no larger
than the maximum. Refinement is clamped to `[0, 8]`. The worst case uses
`1 + MaxSteps + RefinementSteps` height samples. Refinement improves a detected
crossing; more march steps are needed to find thin features between samples.
The surface variant adds four height samples while relief is active. Both entry
points skip height sampling when the effective relief is zero.

Distance fading shrinks the slab depth between `FadeStart` and `FadeEnd` and skips
height sampling at or beyond the end. Equal or reversed bounds disable distance
fading. An angular fade reduces depth when normalized tangent-space view Z falls
from `0.10` to `0.02`, then bypasses the trace to avoid unbounded offsets. Disabled
paths return the original UV and `Depth = 0`.

The shader computes UV derivatives before tracing and samples the height map
with explicit gradients inside its loops. Supply finite inputs and use float
precision. Start with a small depth, check under camera motion, then adjust
sample counts against the frame budget on the target device. Extra file precision
reduces quantization; it cannot repair incorrect source relief or undersampling.

Filtering is part of the effective height field. Mipmaps and anisotropic filtering
can smooth small features as the view changes. Keep them consistent while
comparing renders. For a precise comparison with a mesh made from the original
height values, use bilinear height filtering, no height mipmaps, and Aniso Level
0. Restore the intended production filtering and inspect motion afterward.
Unity's [anisotropy settings](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Texture-anisoLevel.html)
can otherwise override the apparent filter choice.

## Verify the result

The repository includes a Unity GPU conformance harness that compiles the actual
function using Unity's SRP texture definitions, renders known height fields, and
checks results against analytic intersections. Run it with an installed Unity 6
editor that includes the SRP Core package:

```powershell
.\scripts\test-unity-parallax.ps1 -UnityEditor 'C:\Program Files\Unity\Hub\Editor\6000.3.7f1\Editor\Unity.exe'
```

The script uses the project's Python environment to prepare four generated
material inputs, checks CuPy/PTX height agreement, and creates a temporary Unity
project. It retains analytic results, geometric error measurements, labeled
comparisons, and camera sweeps. Each comparison shows a flat surface with height
normals, POM, and a dense displaced mesh under the same perspective camera and
lighting. See the [validation method](../dev/parallax-validation.md) for its
measurement boundaries and interpretation.

It uses a real D3D11 graphics device, with a five-minute timeout. Licensing and
package import must work on the host. This harness exercises the HLSL wrapper;
it does not create or validate your finished Shader Graph material.

Check the consuming material in the editor:

- With zero depth, the appearance matches the original material.
- A flat white height gives zero offset; a flat lower height moves opposite the
  tangent-space camera direction.
- Seams occlude the expected region as the camera moves, and every map stays aligned.
- Normal direction, UV tiling, object scale, and import precision match the contract.
- Repeating edges, grazing views, and the distance fade behave acceptably in motion.
- Target platform builds compile and meet the frame budget; inspect depth, shadow,
  and clipping behavior in the passes used by the project.
